design/UI_SPEC.md

FIRE ATLAS — UI Spec (mandatory for every UI change)

The dashboard must look like a real NASA-adjacent engineering instrument, not an AI-generated template. Judges have seen a hundred "AI dashboards" today. Ours should feel like software a flight-safety engineer would actually use, and the motion should feel like a mission display booting up.

Reference feel: mission-control consoles, Bloomberg terminal density, Linear/Vercel restraint, scientific instrument panels, F1 telemetry overlays. Not a SaaS landing page.

---

1. Banned (instant "AI slop" signals) — never ship these
- Purple/blue/pink gradients, gradient text, glowing gradient borders.
- Sparkle ✨ / magic-wand / robot icons, "AI-powered" badges, emoji anywhere in the UI.
- Glassmorphism blur panels everywhere; heavy drop shadows; everything border-radius: 16px+.
- Big centered hero with a slogan. Marketing copy ("Unlock insights", "Revolutionize", "Seamlessly").
- Generic stat cards with a big number + tiny green "↑ 12%".
- Lorem ipsum, fake numbers, placeholder avatars. Every number on screen comes from data.
- Default Plotly look (modebar, default fonts, default colorbar, white hover boxes).
- Spinners. Use skeleton lines or a text status ("Loading condition space…").
- Random animation for decoration (bouncing, floating, pulsing everything).

2. Visual system

Color (already in tokens.css — extend, don't replace)
- Surfaces: --bg #05070d, --panel #0b1020, --panel-2 #0f1528 (raised), --line #1c2540, --line-strong #2a3558.
- Text: --text #e6ecff, --muted #7d8bb3, --faint #4a5578.
- Color carries meaning only. Outcome: burned #ff5a1f, self-extinguished #ffc542, no ignition #3fa7ff, unknown #5b6478. Alert/extrapolating #ff2d55. Moon #c9b6ff. Nothing else gets a saturated color. One accent (flame orange) for the primary action only.

Type
- Space Grotesk 600 for panel titles only. Inter for body. JetBrains Mono for every number, unit, ID, citation, and label tag.
- Scale (px): 11 (labels, uppercase, letter-spacing 0.08em) · 13 (body) · 15 (emphasis) · 20 (panel title) · 32 (one hero metric max). No other sizes.
- Numbers: font-variant-numeric: tabular-nums. Always show units in muted color: 34.0 %.

Layout & density
- 8 px grid. Panel padding 16. Gaps 12. Radius 6 px max (4 px for tags/inputs).
- Panels are separated by 1 px --line hairlines, not shadows.
- Every panel has a header row: small mono index (01), uppercase label, and a right-aligned status (READY / 234 TESTS / EXTRAPOLATING).
- Information density is a feature: compact rows (28–32 px), aligned columns, no wasted whitespace. But the atlas gets the space: ≥ 70% width on desktop.
- Small corner tick marks / crosshair details on the atlas frame (instrument feel) — subtle, 1 px, --line-strong.

Components
- Tags: mono 11 px, 1 px border, 4 px radius, e.g. MEASURED ASSUMED FROM RANGE QUIESCENT. Assumed = dashed border.
- Citation chip: [PSI-25 · B3] mono, underline on hover, click → selects the point on the atlas and opens its test card.
- Inputs: dark fields, 1 px border, focus = accent border + no glow. Units inside the field, right-aligned, muted.
- Buttons: primary = solid flame orange, dark text, no gradient. Secondary = outline. Icon library: lucide-react only, 16 px, stroke 1.5.
- Tables: mono numbers right-aligned, zebra off, hover row --panel-2.
- Empty states: one honest line + what to do ("No tests match these filters. Clear outcome filter.").

The Atlas (hero) — Plotly styling
- displayModeBar: false; transparent paper_bgcolor/plot_bgcolor; grid --line; axis titles mono 11 px muted; tick labels mono.
- Custom HTML hover/tooltip (or Plotly hoverlabel with bgcolor --panel-2, border --line-strong, mono font) — never default white.
- Markers: size 5–7, opacity 0.85, no outline; selected point = larger + white ring; hovered investigation = others dim to 0.15.
- Habitat markers: diamonds, white 1.5 px outline, label in mono uppercase with a thin leader line.
- Slow idle camera orbit (≈ 1 rotation / 60 s) when the user hasn't interacted for 8 s; stops on any interaction.

3. Motion (use motion — the Framer Motion package — for React; CSS for simple hovers)
Motion must communicate, not decorate. Timing tokens:
- fast 120ms (hover, press) · base 220ms (panels, drawer) · slow 600ms (data reveals). Easing cubic-bezier(0.2, 0.8, 0.2, 1).
- Boot sequence (first load only, ≤ 1.8 s total, skippable by any click): hairline frame draws in → panel headers type in (mono) → status lines tick ("PSI INDEX · 25 INVESTIGATIONS", "TESTS · 1,xxx") → atlas points fade/scale in by investigation in a stagger (40 ms per group). Real counts only.
- Number changes: count-up/down over 400 ms (tabular nums so nothing jitters).
- Habitat selection: camera eases to the habitat marker (Plotly relayout of scene.camera animated over ~800 ms), a ring pulses once around it, and a one-line readout slides in.
- Extrapolating state: the panel border shifts to --alert, a 1 px scanline sweeps once across the atlas, status reads EXTRAPOLATING — NO PSI TESTS IN THIS REGION. Once, not looping.
- SI briefing: text streams in sentence by sentence; each citation chip appears as its sentence completes, and the cited point pings on the atlas.
- Drawer/test card: slides up 220 ms; content stagger 30 ms per row.
- Respect prefers-reduced-motion: disable boot sequence, orbit, and sweeps.

Part A — PSI harvester (pipeline/harvest.py)

Goal: download everything we might need from PSI once, so the rest of the project never depends on the live API.

A1. Discover investigations
- Query the search endpoint with each of these terms: combustion, flame, fire, smoke, droplet, flammability, soot, aerosol.
  https://psi.nasa.gov/geode-py/ws/repo/search?term=<term>&source=psi&type=investigation
- Response is Elasticsearch-shaped: hits.hits[]._source, ID in _source["Accession"] (e.g. PSI-26). Check whether results are paginated (total vs returned count); if total > returned, find the paging params (try size/from, page) and fetch all.
- Deduplicate by Accession. Keep the _source of each hit (it has Research Area, SubResearch Area, Acronym, Flight Platform, Experiment Hardware, dates, etc.).
- Keep only investigations whose Research Area / SubResearch Area / title / keywords relate to combustion or fire (smoke/aerosol detection like SAME, SAME-R, DAFT counts). Log the ones you drop and why to data/raw/excluded.json. When unsure, keep it.

A2. Fetch details
- For each kept ID: https://psi.nasa.gov/geode-py/ws/repo/investigations/<ID> → save as data/raw/investigations/<ID>.json (pretty-printed, untouched).

A3. Download experimental tables
- Each detail JSON has experimentalTable (list, may be null/empty). Each entry has file_name.
- Download: GET https://psi.nasa.gov/geode-py/ws/studies/<ID>/download?file=<urlencoded file_name>&version=1&redirect=false → the body is a plain-text signed S3 URL. GET that URL to get the file bytes.
- Save to data/raw/tables/<ID>/<file_name> (keep original name). Some may be .xlsx — save as-is.
- Also look in the detail JSON for any other data-file lists (inspect keys; e.g. files, dataFiles, resources). Don't download large binaries (video/images > 5 MB) — just record them in the manifest.

A4. Manifest + inventory
Write data/raw/manifest.json: one entry per investigation:

  "research_area": "...", "sub_research_area": "...", "start_date": "...", "end_date": "...",
  "related": ["PSI-26"], "tables": [{"file": "...", "path": "data/raw/tables/PSI-25/...", "rows": 129, "bytes": 16590}],
  "other_files": [ ... ], "errors": [] }

Write data/raw/INVENTORY.md — a human-readable report, this is the most important output of Part A:
- A table: ID | acronym | title | #tables | total rows | DOI.

- A "columns of interest" summary: for each table, which columns look like O₂ concentration, pressure, flow/air speed, fuel/material, sample geometry (thickness/diameter/width/length), and outcome (ignition, extinction, burn time, self-extinguished). Just identify them — do not normalize yet (that's Task 02).

A5. Robustness
- Use requests with a 30 s timeout, 3 retries with backoff, a polite 0.3 s delay between requests, and a plain User-Agent fire-atlas-hackathon/0.1.
- Re-running must be safe: skip files already downloaded (add --force to re-download).
- Read CSVs with encoding="utf-8-sig" and fall back to latin-1.
- Add pipeline/requirements.txt (requests, pandas, openpyxl).
